# oh-my-patent 0.4.0

## English

Version 0.4.0 adds a portable Agent Skill alongside the original Archimedes plugin.
The default plugin still provides 14 agents, 6 skills and 9 commands; use
`adapt install --mode skill --tool <host>` to choose the additional portable form.

- The Skill bundles role/capability references, templates and a self-contained
  Node.js >=22 runtime. It can move independently of the repository and global CLI.
- Install the portable Skill with Skills CLI, a repository ZIP or the project CLI;
  see the [installation choices](../../README.md#skill-installation).
- Plugin and Skill installation/removal retain separate ownership. Skill operations
  preserve plugin files, customizations and workspace configuration; project state
  migration remains an explicit, reviewed action.
- Portable workflows coordinate persistent writes, recover interrupted installation
  transactions, audit approved remote disclosure and reject stale figure reviews.
- The independent `oh-my-patent-skill` npm package inherits version `0.4.0`, contains
  46 files and has no runtime npm dependencies or install scripts. Both stable npm
  packages use `latest`; standalone Skill publication remains a separate manual workflow.
- The original npm workflow now triggers on `release.published`, including publishing
  a draft GitHub Release. CI verifies both npm archives, the Skill ZIP, checksums,
  relocated runtimes and standalone publication with an npm dry-run.

First-wave host installation/workflow acceptance was confirmed by the maintainer
on 2026-10-05. This confirmation is recorded in the acceptance ledger and host
registry; no new host run counts, host versions or execution traces are asserted.
Wave-two hosts, combined plugin/Skill host activation, optional image providers,
third-party installers and marketplace submission remain outside that record.
Separate [Skills CLI installation checks](../compatibility.md#skills-cli-installation-checks)
cover the portable package's files and local runtime for all three first-wave hosts.

After npm publication, choose plugin or Skill mode. Replace `<host>` with
`claude-code`, `codex` or `opencode`, and `<workspace>` with your workspace path:

```sh
# Choose one mode for your selected host.
npx oh-my-patent@0.4.0 adapt install --tool <host> --workspace-dir <workspace>
npx oh-my-patent@0.4.0 adapt install --mode skill --tool <host> --workspace-dir <workspace>

# Standalone Skill: download, extract, then register the complete directory.
npm pack oh-my-patent-skill@0.4.0 --ignore-scripts
```

For the standalone package, extract the archive and copy the complete `package`
directory into your host's Skill location, then select `oh-my-patent`. See the
[manual installation steps](../skill.md#standalone-skill-package-installation).

## 中文

0.4.0 在原有 Archimedes 插件之外新增便携 Agent Skill。默认插件继续保留
14 个智能体、6 项技能、9 个命令；使用 `adapt install --mode skill --tool <host>`
选择新增的 Skill 形式。`<host>` 按所用宿主替换为 `claude-code`、`codex`
或 `opencode`；两种模式均支持这三个宿主。

- Skill 包含角色与能力参考、模板和独立 Node.js >=22 运行时，可脱离源码仓库
  与全局 CLI 搬移使用。
- 便携 Skill 支持 Skills CLI、仓库 ZIP 和项目 CLI 三种安装方式，
  详见[安装选项](../../README.zh-CN.md#安装-skill)。
- 插件与 Skill 分别管理安装、卸载和文件归属。Skill 操作保留插件文件、用户修改
  与工作区配置；已有项目状态迁移仍需显式检查与执行。
- 便携工作流协调持久化写入、恢复中断安装事务、审计已授权的远程披露，
  并使过期附图审查失效。
- 独立 npm 包 `oh-my-patent-skill` 自动继承 `0.4.0`，包含 46 个文件，
  无运行时 npm 依赖或安装脚本。两个稳定版 npm 包均使用 `latest`；
  独立 Skill 仍由单独的手动工作流发布。
- 原 npm 工作流改为监听 `release.published`，覆盖草稿 Release 发布。
  CI 校验两个 npm 归档、Skill ZIP、校验和、搬移后的运行时，并进行独立 Skill 发布 dry-run。

维护者已于 2026-10-05 确认第一批宿主的安装与工作流验收完成，该确认已写入
验收记录与宿主登记表。本次发版准备不新增宿主执行次数、版本号或运行轨迹声明。
第二批宿主、插件与 Skill 同时激活、可选图像服务、第三方安装器及市场提交
不在这项验收记录内。

## Maintainer release steps / 维护者发布步骤

These steps record the original 0.4.0 publication process. New release tags use
[automatic Release publication](../skill.md#automatic-release-publication).
以下记录 0.4.0 的原始发布流程；新版本标签使用上述自动发布流程。

1. Merge the release PR after its Ubuntu/Windows CI passes.
   发版 PR 的 Ubuntu/Windows CI 通过后合并。
2. Create tag `0.4.0` at that merge commit and publish a GitHub Release using these notes.
   在该合并提交创建 `0.4.0` 标签，使用本说明发布 GitHub Release。
3. Check the automatically triggered **Node.js Package** workflow for the original npm package.
   检查自动触发的 **Node.js Package** 工作流，确认原 npm 包发布结果。
4. Run **Publish standalone Skill** on the same tag with `dry_run: true`, then
   with `dry_run: false` to publish `oh-my-patent-skill`. Its token must have publication access.
   在同一标签先执行独立 Skill 的 dry-run，再关闭 dry-run 发布；所用 token 必须有发布权限。

These notes prepare the release; merging, tagging, creating a Release and uploading
npm packages are separate actions. 本说明用于准备发版；合并、标签、创建 Release
和上传 npm 包分别执行。

See [installation modes](../skill.md), [compatibility](../compatibility.md) and
[acceptance source](../../specs/002-skill-first/verification.md#release-040-acceptance-confirmation).
